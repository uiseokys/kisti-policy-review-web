# Durable sync implementation

`src/storage.ts` stores per-item drafts and local source documents in IndexedDB, keyed by owner and assignment. `src/sync.ts` exposes the requested `SyncEngine` API. `edit()` writes the draft before it resolves and schedules a 750 ms debounce by default. `flush()` sends a version CAS command with a persistent mutation ID. Only a successful server ACK changes an item to `saved`.

The engine preserves pending drafts during server load, serializes writes per item, advances a newer draft to the ACK version after an in-flight edit, and retains conflict state until explicit `resolve('server' | 'local', mergedLabels?)`. Transient failures retry with exponential delay up to 30 seconds. Locked and forbidden failures preserve the draft and stop automatic retry, including after reload. `retry(itemId)` explicitly clears the error, retains labels/base version/mutation ID, and flushes when online; another server rejection remains terminal. A new edit also clears terminal state. `getSnapshot()` returns a cached reference between changes for React `useSyncExternalStore`.

Integration: create one engine per authenticated owner and assignment with the backend as `transport`, call `await start()`, subscribe through `useSyncExternalStore(engine.subscribe, engine.getSnapshot)`, call `edit(itemId, labels)` for changes, `flush()` before navigation or submit, `retry(itemId)` only on an explicit retry action for a failed item, and `stop()` on teardown. Call `await persist()` before releasing a single-writer lock or navigating away; it waits for all queued local writes and rejects if persistence fails. A stopped engine ignores late server loads. `pending > 0` blocks submit. Use `setOnline(navigator.onLine)` from browser online/offline events. Source CSV remains local via `saveLocalDocument` / `loadLocalDocument`.

Verification: `tests/sync.test.ts` uses real IndexedDB behavior through `fake-indexeddb` and a purpose-built CAS transport. It covers owner/assignment isolation, offline reload, duplicate ACK after retry, two-device conflict and both resolution choices, in-flight edits, terminal failure and explicit recovery, local documents, stable snapshots, teardown during an in-flight save, delayed and failed local writes, and a late server load after stop. The focused sync suite passed 15/15, the full project suite passed 31/31 across seven files, and `tsc -b` passed. Remote Supabase integration was not run.
